# Configuration

## Canonical Config Root

All user-editable configuration files live under the **`configs/`** directory at the project root:

```
configs/
├── training/              ← Training YAML configs (canonical location for user configs)
│   ├── base.yaml          ← General-purpose default
│   ├── standard.yaml      ← Balanced configuration (stable learning)
│   ├── aggressive.yaml    ← Fast convergence settings
│   ├── curriculum.yaml    ← Staged difficulty (training aids → full BVR)
│   ├── presets/           ← Scenario presets (simple.yaml, gui.yaml)
│   └── archived/          ← Historical reference configs (not actively used)
├── visualization/
│   ├── default.yaml       ← General-purpose visualization
│   ├── live_view.yaml     ← Interactive live view (low DPI, faster interval)
│   ├── video_export.yaml  ← High-quality video recording
│   └── awacs.yaml         ← AWACS figure-8 scenario
├── tacview/
│   └── default.yaml       ← Tacview ACMI generation defaults
├── gui/
│   └── default.yaml       ← GUI startup preferences (startup tab, defaults)
└── shared/
    ├── paths.yaml          ← Canonical output directory defaults
    └── runtime.yaml        ← Shared worker / resource defaults
```

The package also ships built-in defaults under `src/air_to_air_rl/rl/configs/` (training)
and `src/air_to_air_rl/visualization/configs/` (visualization). These are fallbacks — the
project-level `configs/` directory always takes precedence.

> **Rule of thumb**: Put your configs in `configs/training/` and `configs/visualization/`.
> Never modify files inside `src/`.

## Config File Locations

| Type | Canonical (project) | Fallback (package) |
|------|--------------------|--------------------|
| Training | `configs/training/*.yaml` | `src/air_to_air_rl/rl/configs/*.yaml` |
| Visualization | `configs/visualization/*.yaml` | `src/air_to_air_rl/visualization/configs/*.yaml` |
| GUI | `configs/gui/default.yaml` | (none — returns `{}` if missing) |
| Shared paths | `configs/shared/paths.yaml` | (none — returns `{}` if missing) |
| Shared runtime | `configs/shared/runtime.yaml` | (none — returns `{}` if missing) |

## Config Resolution Order

`utils.config_loader.resolve_training_config(name_or_path)` resolves in this order:

1. **Absolute path** → used as-is
2. **Path with separator** (`/` or `\`) → resolved relative to `project_root()`
3. **Bare name** (e.g. `"aggressive"`) →
   a. `<project_root>/configs/training/aggressive.yaml`
   b. Package `rl/configs/aggressive.yaml`
   c. Package `rl/configs/train_config_aggressive.yaml` (legacy name fallback)

`project_root()` is resolved via `air_to_air_rl.core.paths.project_root()` — it walks up from
the installed package to find the directory containing `pyproject.toml`. The `AIR2AIR_RUNTIME_DIR`
environment variable overrides the runtime-output root (see `core/paths.py`).

## Training Configuration

Training configs are YAML files loaded by `utils.config_loader.load_train_config()`.

```yaml
# configs/training/my_config.yaml

env:
  num_agents_per_side: 2       # agents per side (total = 2×)
  max_steps: 1024              # episode length in ticks
  map_size: 200                # map half-width in km
  agent_aircraft_type: Eurofighter
  opponent_aircraft_type: Eurofighter
  # weapon_config: {}          # optional weapon overrides

model:
  fc_hidden_size: 256          # FC layer width

# PPO hyperparameters
gamma: 0.995
lambda: 0.95
use_gae: true
train_batch_size: 4096
sgd_minibatch_size: 128
num_epochs: 10
vf_loss_coeff: 0.5
entropy_coef: 0.01
kl_coeff: 0.2
clip_param: 0.2
grad_clip: 1.0

# Ray resource allocation
num_env_runners: 4
num_gpus: 1
```

### Reward Configuration

Rewards are assembled from named components. Override them at the `env.reward_config` key.

## Visualization Configuration

Visualization configs control the rendering appearance.

```yaml
# configs/visualization/my_viz.yaml

symbol_mode: nato          # nato | flying_objects | procedural
symbol_size: 32
background_color: "#1a2535"
show_grid: true
grid_color: "#25364a"
coastlines_color: "#5a6e82"
dpi: 150
```

### Symbol Modes

| Mode | Description |
|------|-------------|
| `nato` | MIL-STD-2525C frames (milsymbol.js PNGs) |
| `flying_objects` | Type-specific SVG silhouettes (aircraft type from `Airplane.aircraft_type`) |
| `procedural` | Cairo-drawn shapes (no external files; used in CI/headless) |

> **Note**: Missiles always use `flying_objects/missile_{side}` and SAMs always use `nato/sam_{affiliation}`, regardless of the configured `symbol_mode`.

PNG assets are pre-generated by `visualization/symbols/generate_symbols.js` (requires Node.js). Run it once after cloning to populate `symbols/png/`.

## Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `AIR2AIR_RUNTIME_DIR` | `<project_root>/runtime/` | Override runtime output root (checkpoints, logs) |
| `KMP_DUPLICATE_LIB_OK` | — | Set to `TRUE` on Windows to avoid MKL conflicts |
| `OMP_NUM_THREADS` | — | Set to `1` in profiling scripts to avoid CPU oversubscription |
| `PYTHONUNBUFFERED` | — | Set to `1` by background process launcher for real-time log streaming |
| `RAY_DISABLE_IMPORT_WARNING` | — | Optional: suppress Ray import warnings |
