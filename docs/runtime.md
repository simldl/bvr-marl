# Runtime and Output Directory Conventions

All runtime output is generated at well-known paths that are **gitignored**.
Nothing is written into the source tree (`src/`) or the project's Python package.

## Directory Layout

```
<project_root>/
├── models/                        # Training checkpoints and TensorBoard logs
│   └── <model_name>/
│       ├── train_config.yaml      # Copy of the training config (written by train.py)
│       ├── <ray_tune_run_dir>/
│       │   └── checkpoint_NNNNNN/ # RLlib checkpoint directory
│       └── events.out.tfevents.*  # TensorBoard event files
├── runtime/                       # GUI and process-tracking state (see below)
│   └── gui/
│       ├── logs/                  # Background process log files
│       │   └── <label>_<ts>.log
│       ├── training_processes.json
│       ├── visualization_processes.json
│       ├── tacview_processes.json
│       └── tensorboard_processes.json
└── profiling_results/             # Profiling output (gitignored)
    ├── *.stats
    └── *.txt
```

> The `runtime/` root can be overridden via the `AIR2AIR_RUNTIME_DIR` environment variable.
> See `air_to_air_rl.core.paths.runtime_root()`.

## Artifact → Location Mapping

| Artifact | Default location | Configured via | Gitignored |
|----------|-----------------|----------------|------------|
| RLlib checkpoints | `models/<model_name>/` | `logging.save_dir` in training YAML | Yes |
| TensorBoard event files | `models/<model_name>/` | `logging.log_dir` in training YAML | Yes |
| Saved training config copy | `models/<model_name>/train_config.yaml` | Automatic (written by `train.py`) | Yes |
| GUI process state JSON | `runtime/gui/*.json` | `core.paths.runtime_root()` | Yes |
| GUI background process logs | `runtime/gui/logs/*.log` | `services.training.launch_background_process()` | Yes |
| Tacview ACMI files | Specified by `--acmi` flag | CLI argument | Yes (`*.acmi`) |
| 2D visualization video | Specified by `--save-video` flag | CLI argument | Yes |
| Profiling results | `profiling_results/` | Hard-coded in profiling scripts | Yes |
| Temporary render frames | `temp_*.png` at project root | Generated by visualization | Yes |

## Training Output Paths

Training saves to directories specified in the YAML config under `logging`:

```yaml
logging:
  model_name: "my_model"       # subdirectory name under save_dir
  save_dir: models             # relative to project root (or absolute)
  log_dir: models              # TensorBoard log directory
```

`train.py` resolves relative `save_dir` / `log_dir` values using `os.path.abspath()`,
which means they are relative to the current working directory when `air2air-train`
or `python -m air_to_air_rl.training.train` is invoked.

**Best practice:** Always run training from the project root, or use absolute paths.

## GUI Process State

The GUI uses `services.processes.ProcessMonitor` to track background subprocesses.
State files are written to `runtime/gui/` via `core.paths.runtime_root()`.
These files are regenerated at runtime and are **never committed to version control**.

## Overriding the Runtime Root

Set `AIR2AIR_RUNTIME_DIR` to redirect all runtime output:

```bash
export AIR2AIR_RUNTIME_DIR=/mnt/fast-ssd/air2air_runtime
air2air-train --config my_config.yaml
```

This only affects the `runtime/` subtree (GUI state, process logs).
Training checkpoint output (`models/`) is controlled separately by the training config.
